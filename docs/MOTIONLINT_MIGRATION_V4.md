# v3 到 v4 的迁移

本地包版本为 0.4.0，默认规则为 4，报告格式为 2。历史报告保留原版本；不把历史 v3 总分与当前 v4 总分相减。冻结 v3 算法产生的候选需用 v4 重新检查后参与当前算法比较。

当前修复算法版本为 5：先脚滑，再接缝，最后处理有限碰撞；接缝只修改检测到的异常边界及通道，逐步与总位移界同时执行。正常连续序列返回无需修复。修复算法版本与检测规则版本分别追踪。

## 修复 v4 到 v5（规则不变）

- 脚滑新增支撑脚和根节点协调的有界候选，使用区间范围中心减少单端锚定所需的最大纠偏；骨长和 0.15 米脚滑位移上限仍执行。
- 所有修复步骤逐人物、逐脚比较固定原支撑区间，拒绝距离增加、新增脚滑超速区间或过大峰值；步骤之间还与最初输入比较，避免后续改变接触识别掩盖退步。
- 全部检测项，包括当前修复目标和已经 FAIL 的项，都审查新出现的严重问题位置/区间；评估覆盖丢失不能用分数改善抵消。同一只脚在另一个时间新增严重脚滑，即使累计距离降低也拒绝。
- `repair_report.json` 增加 `support_comparison`，候选增加 `input_support_guard`、`rejection_codes`、`rejection_reasons`、新增严重区间及覆盖审查结果。旧字段保留，历史报告没有这些字段时仍能查看。
- 网页显示固定支撑距离、逐脚结果及全部候选理由。候选通过审查表示可参与选择，每步只应用最终选中的一个。

规则配置、阈值和哈希没有变化；同一规则和输入可以比较修复 v4/v5 的数组结果。v5 wheel 存入 `output/packages/repair-v5/`，历史包与已有修复 UUID 保留。详细工程结果见 [v5 验证](MOTIONLINT_REPAIR_V5.md)。

## 命令行为

- 保留 `check / repair / compare / batch`；均支持 `--config`。
- 检测、修复、比较和批处理统一支持 `--unit-scale`、`--up-axis`、`--joint-map`。这些参数用于 BVH；NPY 使用既定米 / Y 轴规范，不接受重新解释单位或骨架映射。
- `0` 表示通过；`1` 表示质量门未通过或比较发生回归；`2` 表示输入或运行错误。批处理任何输入错误优先返回 2，否则任何质量失败返回 1。空清单、重复报告目录、NaN/Inf、错误 FPS、负单位都不会被当作成功。
- `repair` 输出最终安全候选及完整试验记录，保留原输入。退出 1 的安全候选仍可能改善，但未整体达标。
- 比较不同规则版本或规则哈希的报告默认拒绝。CLI 比较文件时会使用同一配置重新检测双方。

## 实质变化

- 明确提供的地面高度优先于百分位估计。
- 没有模型接触标记时，腾空帧不自动判定为悬浮；模型声明接触但离地仍会告警。
- 碰撞继续是骨架近距风险，不等于蒙皮穿透。缺失头部/手臂映射时明确未评估。
- 序列过短或缺失检测所需数据时明确未评估，完整质量门不能通过。
- 候选增加全关节位移上限和新增严重问题审查。实验消融只用于比较脚本，不是默认修复方式。

阈值与权重没有为了提升通过率而放宽。未经过新真实标注的阈值仍是工程默认值，不能称为已完成真实数据校准。

## 报告追踪

`metadata` 新增格式版本、规则版本/哈希、输入文件哈希、实际评估数组哈希、处理阶段和各检测覆盖情况。`input_sha256` 是来源文件；修复中间候选尚未落盘时，用 `evaluated_array_sha256` 标识真实评估内容。保留原报告字段和历史文件。

BVH 必须确认单位、竖直轴和关节映射；默认米 / Y 轴仅适用于本仓库的既有导出约定。CLI 修复面向 NPY；网页支持完整直接层级映射的 BVH 脚滑 IK，其他 BVH 修复不支持。BVH 检测与回归可以独立运行。
