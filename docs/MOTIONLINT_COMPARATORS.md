# MotionLint 的比较对象与可验证差异

## 场景

目标用户是生成模型开发者、动画开发者，以及处理动作数据的学生和研究者。任务是定位动作问题、判断候选修复是否引入退步、核查实际导出的动画。人工检查成本需要两位同学实际记录，目前没有计时结果。

## 现有方案

| 项目 | 已有能力与来源 | 本项目拟验证的差异 | 不能据此宣称 |
| --- | --- | --- | --- |
| InterGen | 双人动作生成及模型评测脚本 `tools/eval.py`；[官方仓库](https://github.com/tr3e/InterGen) | 对实际 joints22 输入给出逐帧问题区间、修复决策和导出阶段复测 | 不能把 InterGen 生成模型当作自研 |
| LODGE | 音乐舞蹈生成、Foot Refine Block；已有 `metric/foot_skating.py`、节拍和生成质量评测；[官方 README](https://github.com/li-ronghui/LODGE/blob/main/README.md) | 跨来源统一检测、固定原接触区间对照、全量回归拒绝及实际导出复检 | 不能宣称首次检测或修复脚滑 |
| PyMotion | BVH 读写、旋转转换、正向运动学，MIT；[官方仓库](https://github.com/UPC-ViRVIG/pymotion) | 组合为质量门、问题定位和候选审计工作流 | BVH 与 FK 基础能力来自依赖 |
| Blender | 动画编辑、重定向、可视检查；[官方动画功能](https://www.blender.org/features/animation/) | 在播放之前和导出之后自动执行可追溯规则检查 | 不声称替代人工审美或完整碰撞求解 |
| 普通时间平滑 | 本项目自行实现的五帧均值对照 | 有界修复是否比无约束平滑更少破坏骨长及其他指标 | 平滑对照只是工程基线，不代表最强现有研究 |

调研范围限于这些直接相关的开源项目和官方功能说明，不是全面文献综述。新增方案前应补充对应原始论文与实现，避免“唯一”“首创”表述。

## 三个主张及当前证据

1. **多来源统一检测并定位区间。** 已有 InterGen / LODGE / BVH 适配、六项规则与区间报告；准确性需独立人工标注。
2. **接触约束的有限修复与退步拒绝。** 已有位移界、骨长约束、完整复测和候选记录；当前开发集对照可以审查，真实修复有效性和语义需人工核查。
3. **实际导出的动画再次检查。** 已有 BVH 与 Blender 最终骨架采样的开发证据；新盲测六条的阶段实验仍需先完成独立标注和冻结评测。

任何主张都须结合未修复、普通平滑、冻结 v3 算法、v4 完整流程及消融结果。展示平均分变化之外，还报告原支撑区间滑动距离、严格门通过率、拒绝比例、执行失败和人工语义。
