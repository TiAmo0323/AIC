# 修复算法 v5：支撑协调与局部退步审查

## 本轮范围

沿用规则 v4，改进修复和候选审查，不调整检测阈值。本轮结果来自自制工程样例、Windows 本机与仓库外安装验证；不能据此声称真实生成动作的准确率、独立盲测或人工语义验收已经完成。

## 改动原因与方法

原候选主要通过腿部 IK 纠正脚滑。接近伸直的腿难以到达移动后的目标；根节点与脚部使用不同纠偏轨迹，也会留下滑动。v5 增加同一支撑锚点下的根节点/脚部协调候选，对共同漂移采用一致平移，再在有必要的位置执行 IK。区间范围中心使位移预算分配到两端。候选仍受到骨长、逐步位移、总位移及全量复测约束；没有脚滑问题的人物不被修改。

仅比较分数或超速帧数可能掩盖物理退步：滑动集中在较少帧时，总路径仍可能增加；一个人物改善也可能掩盖另一个人物退步。新审查使用原输入的支撑区间，逐人物、逐脚核对累计水平路径、超速区间数量和峰值。所有修复步骤均受约束，后续步骤还与最初输入复查。没有可信支撑区间时报告不可用，不能把缺失检测算作通过。

此外，所有检测项（包括当前修复目标和已经 FAIL 的项）都核对人物、关节、指标和严重问题区间，拒绝新严重问题与评估覆盖丢失。报告保存机器原因码、完整中文显示依据及全部候选；候选可用与最终选择分别理解。

回归反例中，候选分数 94.94 → 97.04、累计滑动距离 0.608 → 0.076 米，却在同一只脚后面的时间区间新增严重滑动。只看分数、路径或超速数量都会漏掉；新审查明确拒绝该候选。该反例属于工程测试，没有计入下面的 45 条对照。

## 回归与实际产物验证

- 完整 CPU 测试：208 通过、10 项可选生成集成跳过。新增用例覆盖分数提高但距离增长、同一只脚在别的时间新增严重滑动、另一人物退步、非脚滑修复引入低速脚漂、已失败项新增严重位置、骨长与位移、未受影响人物、Z-up 和 29.97 FPS，以及 BVH 实际回读。
- 仓库外安装本轮 wheel：34 项核心、修复产物与局部退步审查通过；导入的核心来自 `site-packages`，该目录不存在 `LODGE_api`。
- 前端：8 组检查及生产构建通过。实际浏览器展开了逐脚数据、候选列表与拒绝原因，并下载 NPY 后上传复查。
- 单人 300 帧 / 30 FPS 脚滑工程样例：原始 96.70 FAIL → 数组、BVH、实际 Kenney 角色均 100 PASS；固定支撑距离约 0.4267 → 0 米，最大关节位移约 0.1067 米。
- NPY 手动上传与 BVH 重新导入均创建新任务，实际坐标与对应保存阶段误差为 0。Kenney 视频 300 帧全量解码通过，10 秒、30 FPS，并在浏览器播放。
- 骨长异常工程样例重新执行 v5，四个候选均被拒绝，最终数组保持不变。视频完整性与阶段质量门仍分别判断。

## 复跑方法

从当前仓库安装后运行：

```sh
python scripts/benchmark_motionlint_foot_repair.py --output reports/foot_iteration/reproduced_v5
python -m pytest tests/test_motionlint_support_regression.py tests/test_motionlint_artifacts.py -q
```

脚本生成自制输入、实际修复数组、逐样本报告与 `summary.json`。历史基线必须来自修复 v4 的保存运行，不能用当前算法重跑后称为 v4。已有本机基线可以这样对照；脚本会拒绝输入或规则不一致：

```sh
python scripts/benchmark_motionlint_foot_repair.py --output reports/foot_iteration/reproduced_v5 --baseline reports/foot_iteration/baseline_v4/summary.json --evidence reports/foot_iteration/reproduced_comparison.json
```

公开仓库包含逐样本的哈希与结果，不包含本机任务目录。若缺少历史基线，可在原 `a1412bb` 提交的独立检出中使用同一脚本和计量模块生成 v4 基线；随后核对输入与规则哈希。复制计量脚本不会改变旧修复算法，但必须保留双方源码哈希。
