# v4 实际操作演示与答辩准备

当前视频为带中文讲解和字幕的工程演示草稿，使用一份历史开发动作的副本，不计为新动作或独立盲测。原始文件、修复候选、BVH、角色报告均保留。主片段是实际页面操作录像，末段展示实际执行过的 CLI 输出回放，明确不把输出回放称为实时终端操作。

## 已录制和复查的流程

1. 加载原始动作，展示六项检测、当前规则和整体质量门。
2. 点击时间轴告警，展示人物、关节、区间、数值和阈值，并定位原始视频。
3. 执行 Repair All，展示接受的脚滑/骨长修复、超过总位移上限而拒绝的人物分离，以及不支持的局部碰撞。
4. 显示“候选改善”和“整体达标”。本条分数由 85.0 提高到 90.4，但整体 FAIL，残余脚滑、近距风险和抖动仍需处理。
5. 前后视频联动定位、倍速和播放；导出新的 Kenney 动作，并切到角色阶段检查。
6. BVH 阶段不跳到其他阶段的视频；角色告警定位实际角色视频。

证据：`reports/first_prize/browser/verification.json`、`narrated_video_verification.json`、`demo_provenance.json`，以及 `reports/first_prize/cli_demo/installation.json`。带讲解视频：`output/video/motionlint_v4_narrated_draft.mp4`；原操作录像保留在 `output/video/motionlint_v4_operations.mp4`。这条本机集成案例不能代替固定六条独立盲测阶段审计。

讲解使用 Windows 本机 Microsoft Huihui 合成语音，稿件为 AI 辅助草稿；不是团队成员实际录音。字幕放在独立下栏，保留页面内容。声音和视频分别完整解码核验，正式提交前仍需团队试听、审阅和必要重录。

## 正式视频需要补齐

- 已用仓库外的独立环境实际执行自制 clean、缺陷、修复、回归和输入错误，退出码预期全部符合；视频展示这些输出回放。正式团队演示可使用实时终端操作替换回放。
- 加入实际人工标注与外部安装结果；未完成时不能朗读为既成事实。
- 全程说明近距检测是骨架风险近似，修复接受不是所有项目达标。
- 当前草稿约 3 分 47 秒，音视频完整解码并满足大小范围。补充真实人证后重新剪辑和核验身份信息；草稿本身不代表正式视频验收。

## 答辩要点

| 问题 | 有依据的回答 |
| --- | --- |
| 为什么使用规则检测？ | 当前问题具有可解释的几何和时间约束，能够定位具体关节与帧；阈值仍需真实人工开发集验证。 |
| 120 条 F1 为 1.00，是否可靠？ | 只说明单姿态可控缺陷的限定测试通过，真实准确率需要独立标注的 19 条盲测。 |
| 修复提高 26.66% 是否证明目标达成？ | 这是开发集固定原支撑区间的累计距离中位数，无人工确认的脚滑子集和语义证据，不能直接作为最终验收。 |
| 为什么有候选被拒绝？ | 即使目标指标改善，超过位移上限、骨长约束或配置中的回归条件都不能进入最终选择。 |
| 能检测真实穿模吗？ | 当前骨架距离提供近距风险，不能作为网格穿透真值；需要看角色或增加表面几何验证。 |
| 别人如何使用？ | CPU 核心可安装 wheel，不需模型权重；Windows 两个干净环境已通过，外部同学和 Linux 实测待完成。 |
| 生成模型与自研贡献是什么？ | InterGen / LODGE 提供动作来源，自研集中于统一检测、有限修复、拒绝与阶段复检；第三方原有的脚滑修复需如实引用。 |
| 开源许可证确定了吗？ | 源码候选仍在本地审阅；原项目缺少根许可证，旧辅助代码来源须确认，权重、人体模型和角色不进入公开包。 |

AI 辅助开发、真实成员审核及分工由团队据实确认。提交前核对机器结果、报告、录像和源码哈希一致。
